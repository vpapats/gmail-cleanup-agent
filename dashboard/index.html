01 / Overview

At a glance

These values come from the production configuration and workflow.

Operation mode—Controls whether eligible messages can move to Trash.
AI model—Set in the daily and weekly workflows.
Trash confidence—Minimum classification confidence.
Daily review cap—Maximum emails reviewed per run.
1 · DiscoverScan unreviewed inbox messages using the configured Gmail query.

4 · Act & verifyApply labels, move eligible mail to Trash after summary delivery, and verify the sent email.

04 / Decision rules
What the automation decides
Open classifier.py ↗

      

        
Kept
Useful messages and records remain available and receive the configured kept label.

        
Action needed
Messages requiring a concrete reply, decision, payment, approval, schedule, or task.

        
Digest & Trash
Low-value inbox noise is summarized first and can then move to recoverable Gmail Trash if all gates pass.

      

      

        
Hard protections
These signals block a model decision to digest and trash.
Product-specific warranty records are recognized by feedback.py; a promotion offering a new warranty is treated differently.

        
Initial protection signals
The initial rules mark these as kept. The model may reconsider caution signals, while hard protections remain enforced.

        
Inbox-noise patterns
These are initial signals, not a final delete rule.

        
Trash gate
Starred messages are also checked again during application. Low-confidence digest decisions are deferred.

06 / Evidence
How to verify a result
Reliability design ↗

      

        
Daily run evidence
The workflow uploads a 30-day audit artifact containing run-result.json, JSONL, and CSV records. A valid daily result requires the triage step, errors=0, summary_sent=1, a non-empty artifact, and a read-back of the exact SENT summary with receipt dates.
Inspect daily runs ↗

        
Corrections & learning
Messages marked AI/Wrongly-Trashed are restored and reviewed. Completed feedback IDs live as encrypted state on the gmail-fomo-state branch; this page does not decrypt or expose them.
View state handling ↗

      

      
Limit: GitHub scheduling is best effort. The watchdog uses GitHub Actions too, so a GitHub-wide schedule outage can affect both. See the documented reliability boundary.
